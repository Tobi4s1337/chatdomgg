# Twitch OAuth scopes — recipes + exhaustive table

How to use this file
- Building something common? Start from a **recipe** (section 1) — copy the scope strings.
- Need a specific endpoint/event? Look it up in the **generated table** (section 3), or run
  `node scripts/token.ts scopes "<endpoint name | eventsub type | scope>"`.
- Request **only** scopes you use: Twitch may suspend apps that over-ask, and users trust short lists.
- Scopes are granted **per (client ID, user)**. App access tokens carry no scopes, but endpoints that
  accept "app token + prior authorization" check the scopes the relevant user granted earlier.
- The table is generated by `scripts/gen-scopes.ts` from `references/official/authentication_scopes.md`,
  cross-checked against every Helix endpoint's and EventSub type's *Authorization* section
  (items found only by the cross-check are marked †). Regenerate after `scripts/refresh-docs.sh`.

## 1. Scope recipes

Notation: **B** = broadcaster's token/grant, **Bot** = bot account's grant, **M** = a moderator's grant.
"No scope" items still need *some* token (WebSocket: any user token; webhook: app token).

### 1.1 Chatbot (cloud bot with its own account + Chat Bot badge) — the recommended setup
| Who | Scopes | Why |
|---|---|---|
| Bot | `user:read:chat user:write:chat user:bot` | read chat via EventSub `channel.chat.message`, send via Send Chat Message, act as a bot with an app token |
| B | `channel:bot` | lets your app (app token) place the bot in this channel's chat; not needed if the bot is a mod |
| Bot (optional) | `moderator:manage:announcements` | Send Chat Announcement (bot must be mod) |
| Bot (optional) | `moderator:manage:banned_users moderator:manage:chat_messages moderator:manage:warnings` | timeouts/bans, delete messages, warn (bot must be mod) |
| Bot (optional) | `moderator:manage:shoutouts` | `/shoutout` via Send a Shoutout |
| Bot (optional) | `user:manage:whispers` | send/receive whispers |

Send messages with an **app token** (`sender_id`=bot, `broadcaster_id`=channel) → badge. With the bot's
**user token** it also works (no badge). Read chat over WebSocket (bot user token) or webhook/conduit (app token).

### 1.2 "Installed" bot / chat tool that speaks as the broadcaster
`user:read:chat user:write:chat` from **B** only. Simplest for a hackathon demo; messages appear from the streamer.

### 1.3 Stream alerts overlay (OBS browser source fed by your backend)
| Event | EventSub type | Scope (from **B**) |
|---|---|---|
| Follow | `channel.follow` v2 | `moderator:read:followers` (B or a mod; condition needs `moderator_user_id`) |
| Sub / resub / gift | `channel.subscribe`, `channel.subscription.message`, `channel.subscription.gift`, `channel.subscription.end` | `channel:read:subscriptions` |
| Cheer / Bits | `channel.cheer`, `channel.bits.use` (all Bits usage incl. Power-ups) | `bits:read` |
| Raid in | `channel.raid` (`to_broadcaster_user_id`) | none |
| Channel points redemption | `channel.channel_points_custom_reward_redemption.add` | `channel:read:redemptions` (or `channel:manage:redemptions`) |
| Automatic rewards (gigantify, message effect…) | `channel.channel_points_automatic_reward_redemption.add` v2 | `channel:read:redemptions` / `channel:manage:redemptions` |
| Custom Power-up redeemed | `channel.custom_power_up_redemption.add` | `bits:read` |
| Hype train | `channel.hype_train.begin/progress/end` **v2** | `channel:read:hype_train` |
| Goals | `channel.goal.begin/progress/end` | `channel:read:goals` |
| Polls / predictions (display) | `channel.poll.*`, `channel.prediction.*` | `channel:read:polls`, `channel:read:predictions` |
| Charity | `channel.charity_campaign.*` | `channel:read:charity` |
| Ads starting | `channel.ad_break.begin` | `channel:read:ads` |
| Shoutouts | `channel.shoutout.create/receive` | `moderator:read:shoutouts` |
| Go live / offline / title change | `stream.online`, `stream.offline`, `channel.update` | none |
| Chat on screen | `channel.chat.message`, `channel.chat.notification` (sub/raid/announcement notices in chat) | `user:read:chat` from the reading user (B or Bot) |

Typical one-liner for **B**:
`moderator:read:followers channel:read:subscriptions bits:read channel:read:redemptions channel:read:hype_train channel:read:goals channel:read:polls channel:read:predictions user:read:chat`

### 1.4 Moderation tool (acting as a moderator **M**, or B)
| Feature | Scope |
|---|---|
| Ban/timeout/unban + read bans | `moderator:manage:banned_users` (read-only: `moderator:read:banned_users`, `moderation:read`) |
| Delete messages, pin/unpin messages | `moderator:manage:chat_messages` |
| Warn users | `moderator:manage:warnings` |
| AutoMod queue (`automod.message.hold` v2, Manage Held AutoMod Messages) | `moderator:manage:automod` |
| AutoMod settings | `moderator:read:automod_settings` / `moderator:manage:automod_settings` |
| Blocked terms | `moderator:read:blocked_terms` / `moderator:manage:blocked_terms` |
| Chat settings (slow/sub/emote-only…) | `moderator:read:chat_settings` / `moderator:manage:chat_settings` |
| Shield mode | `moderator:read:shield_mode` / `moderator:manage:shield_mode` |
| Suspicious users (low-trust) | `moderator:read:suspicious_users` / `moderator:manage:suspicious_users` |
| Unban requests | `moderator:read:unban_requests` / `moderator:manage:unban_requests` |
| Chatters list | `moderator:read:chatters` |
| Which channels do I moderate | `user:read:moderated_channels` |
| Everything-feed `channel.moderate` **v2** | ALL of: (`moderator:read:blocked_terms`\|manage) (`moderator:read:chat_settings`\|manage) (`moderator:read:unban_requests`\|manage) (`moderator:read:banned_users`\|manage) (`moderator:read:chat_messages`\|manage) (`moderator:read:warnings`\|manage) `moderator:read:moderators` `moderator:read:vips` |
| `channel.ban` / `channel.unban` events | `channel:moderate` |
| Add/remove mods, VIPs (broadcaster only) | `channel:manage:moderators`, `channel:manage:vips` |

### 1.5 Channel-points game / economy
`channel:manage:redemptions` (create/update/delete custom rewards; set redemptions FULFILLED/CANCELED —
**only for rewards created by the same client ID**) + `channel:read:redemptions` is implied by manage.
Channel points (and polls, predictions, commercials) exist only for **affiliates/partners** — test with such an account (403 otherwise). Add the chatbot recipe to announce results. EventSub: `channel.channel_points_custom_reward_redemption.add`.

### 1.6 Polls & predictions controller (stream deck / AI host)
`channel:manage:polls channel:manage:predictions` from **B** (manage implies read for the EventSub
begin/progress/end/lock events). Only **affiliates/partners** can run polls/predictions.

### 1.7 Other common features
| Feature | Scope (B unless noted) |
|---|---|
| Update title/category/tags, create stream markers | `channel:manage:broadcast` |
| Create clips | `clips:edit` (Create Clip From VOD / clip downloads: `channel:manage:clips` or `editor:manage:clips`) |
| Start/cancel a raid | `channel:manage:raids` |
| Run ads / snooze / read schedule | `channel:edit:commercial`, `channel:manage:ads`, `channel:read:ads` |
| Subscriber list / check a user's sub | `channel:read:subscriptions` (B) / `user:read:subscriptions` (viewer) |
| Followed channels of a viewer | `user:read:follows` |
| Viewer's emotes (for an emote picker) | `user:read:emotes` |
| Stream schedule | `channel:manage:schedule` |
| VIPs | `channel:read:vips` / `channel:manage:vips` |
| Guest Star | `channel:read:guest_star` / `channel:manage:guest_star` (mods: `moderator:*:guest_star`) |
| Change bot's name color | `user:manage:chat_color` (Bot) |
| "Sign in with Twitch" only | no scope (Get Users works without); add `user:read:email` (+ `openid` for OIDC) to get e-mail |
| Extension config/activation for a broadcaster | `channel:manage:extensions`, `user:edit:broadcast`, `user:read:broadcast` |

## 2. Gotchas
- `channel.follow` **v1 is gone**; v2 needs `moderator:read:followers` and a `moderator_user_id` condition.
- Hype train **v1 types were decommissioned 2025-12-04** — subscribe to v2 (same scope).
- `channel:moderate` is only used by a few EventSub types (`channel.ban`, `channel.unban`, …); most
  moderation endpoints use granular `moderator:*` scopes.
- IRC scopes `chat:read`/`chat:edit` do **nothing** for EventSub chat or Send Chat Message; use `user:read:chat`/`user:write:chat`.
- `whispers:read` was PubSub-only; PubSub is shut down — use `user:read:whispers`/`user:manage:whispers`.
- Adding scopes later requires sending the user through `/authorize` again (with all old + new scopes; use `force_verify=true` to make the consent screen appear).
