## 2. Authorization model for `channel.chat.*`

Every `channel.chat.*` / `channel.chat_settings.update` subscription has the condition
`{ broadcaster_user_id: <channel>, user_id: <the account you read chat AS> }` — usually your bot.

| You subscribe with… | Needs | Notes |
|---|---|---|
| **User token** of `user_id` (required for WebSocket transport) | `user:read:chat` on that token | Simplest. Counts toward the bot's **100 concurrent joined channels** unless the bot is broadcaster or mod there. Bot does *not* appear under "Chat Bots" in Users in Chat. |
| **App token** (webhook or conduit transport) | the `user_id` user authorized your client with `user:read:chat` + `user:bot`, AND the broadcaster authorized `channel:bot` **or** the bot is a moderator | App-token joins aren't join-rate-limited; joins authorized via `channel:bot` don't count toward the join limit. Only with app token **+ `channel:bot`** (mod status is not enough) is the bot listed under **Chat Bots** in Users in Chat (never for the broadcaster's own account). |

- Subscribing joins the chat room; the join lasts until the subscription is disabled (WebSocket closed,
  revoked, deleted).
- `403 "subscription missing proper authorization"` = missing scope/authorization, the bot is banned or
  timed out in that channel, or the concurrent-join limit is reached.
- If the bot is banned/timed out later, *all* its subscriptions for that channel are **revoked**
  (`status: "chat_user_banned"` etc. — see `status` values of Get EventSub Subscriptions). Timeouts give no
  duration, so you must re-subscribe yourself after a while.
- `channel.chat.user_message_hold/update` never need `channel:bot`/mod: they're about *your own* messages.
- WebSocket limits per user token: 3 connections with enabled subs, 300 enabled subs per connection,
  subscribe within 10 s of `session_welcome` or the socket closes (4003). Details: **twitch-eventsub** skill.

## 3. channel.chat.message

Fires for **every** message in the room, *including messages your bot sent itself* (unlike IRC, which never
echoed your own PRIVMSG). Not delivered: messages from users marked **restricted** suspicious users (only
moderators see those via `channel.suspicious_user.message`), messages held by AutoMod until approved.

Key fields (full typed shape: `assets/templates/chat-types.ts` → `ChatMessageEvent`; raw reference tables are in the twitch-eventsub skill's official snapshot):

| Field | Meaning / gotcha |
|---|---|
| `broadcaster_user_*` | The channel (condition broadcaster). |
| `chatter_user_id/_login/_name` | Sender. `_name` is the display name (may contain non-ASCII); `_login` is lower-case. |
| `message_id` | UUID. Use for replies (`reply_parent_message_id`), deletion (Delete Chat Messages), pinning, and to match `channel.chat.message_delete`. |
| `message.text` | Plain text. For replies it **starts with `@parentlogin `** (auto-inserted by Twitch). |
| `message.fragments[]` | Ordered render model — see §4. |
| `message_type` | `text`, `channel_points_highlighted`, `channel_points_sub_only`, `user_intro`, `power_ups_message_effect`, `power_ups_gigantified_emote`. |
| `badges[]` | `{set_id, id, info}` in **this** channel. Read per message; users can change badges any time. |
| `cheer` | `{bits}` or null. |
| `color` | `#RRGGBB` or **empty string** if never set → you need a fallback. |
| `reply` | null or `{parent_message_id, parent_message_body, parent_user_*, thread_message_id, thread_user_*}` — "thread" = first message of the reply chain. |
| `channel_points_custom_reward_id` | Set for "send a message" type channel point rewards. |
| `source_broadcaster_user_*`, `source_message_id`, `source_badges` | Non-null only for shared-chat messages that originated in **another** channel. |
| `is_source_only` | Shared chat: message delivered to the source channel only. |

Official example payloads (verbatim) are in `scripts/fixtures/channel.chat.message.json` and
`channel.chat.message.shared.json`.

## 4. Message fragments & badges

`message.fragments` splits `message.text` into typed pieces, in order. Concatenating every `fragment.text`
reproduces `message.text`. Each fragment always has `type` and `text`; the matching metadata object is set
and the others are null:

| `type` | Metadata | Render as |
|---|---|---|
| `text` | — | text node |
| `emote` | `emote: {id, emote_set_id, owner_id, format: ["static"] \| ["static","animated"]}` | `<img>` from the emote CDN template (rendering.md). `owner_id` "0" for globals. |
| `cheermote` | `cheermote: {prefix (lower-case), bits, tier}` | Get Cheermotes tier image + color. |
| `mention` | `mention: {user_id, user_login, user_name}` | highlighted `@name`. |
| `gif` (since 2026-07-16) | `gif: {id, url}` — the changelog calls the id `gif_id`; read both | `<img src=url>` with the URL **unmodified**; `text` is the GIF title (good `alt`). |

- Treat unknown future types as text (`fragment.text` is always there).
- Fragments in AutoMod / held-message / suspicious-user events are slimmer (emote has only `id` +
  `emote_set_id`; no mention/gif types documented there).
- Emote set ids: `emote_set_id` lets you group/lookup via Get Emote Sets; you don't need it to render.

**Badges**: `{set_id, id, info}`. Resolve the image by `set_id` + `id` against Get Global Chat Badges and Get
Channel Chat Badges (channel wins for `subscriber`/`bits`). `info` is only used for subscriber months
(`set_id: "subscriber", id: "12", info: "16"` = 12-month badge tier, 16 months subbed). Founders carry
`founder` instead of `subscriber`. Permission derivation: `broadcaster` > `moderator` > `vip` >
`subscriber`/`founder` (commands-and-bots.md).

## 6. Deletion & clearing

Overlays and chat UIs **must** honor these or moderated content stays on stream.

| Type | Event fields | Action |
|---|---|---|
| `channel.chat.message_delete` | `target_user_id/_name/_login`, `message_id` | remove that one message |
| `channel.chat.clear_user_messages` | `target_user_id/_name/_login` | user banned or timed out: remove all their messages |
| `channel.chat.clear` | broadcaster only | `/clear`: remove all messages (Twitch resets non-mod views; messages aren't marked deleted) |

IRC equivalents: `CLEARMSG` = message_delete; `CLEARCHAT` with a user = clear_user_messages (IRC adds
`ban-duration` for timeouts — EventSub doesn't; use `channel.ban` with `channel:moderate` if you need it);
`CLEARCHAT` without user = clear.

## 7. channel.chat_settings.update

Event = the **new** full state only: `emote_mode`, `follower_mode`, `follower_mode_duration_minutes` (null if
off), `slow_mode`, `slow_mode_wait_time_seconds` (null if off), `subscriber_mode`, `unique_chat_mode`. Diff
against your cache to know what changed. It is not sent on join (unlike IRC ROOMSTATE) — call **Get Chat
Settings** (`GET /helix/chat/settings?broadcaster_id=`) right after subscribing. Use it to pre-empt drops
(don't send in sub-only mode if your bot isn't a sub/mod; respect slow mode wait time if not mod/VIP).

## 8. channel.chat.user_message_hold / update

For the **user in the condition** (your bot or the user of a chat client): "your message was held by
AutoMod" (`message_id`, `message{text, fragments}`) and later `status: approved | denied | invalid`.
Useful for chat clients; a bot usually just reacts to Send Chat Message returning
`is_sent:false, drop_reason.code:"automod_held"`.

## 9. Shared chat

Shared Chat merges up to several channels' chats. Effects on you:

- Messages/notices from other participants are mirrored into your channel's events with
  `source_broadcaster_user_id/_login/_name`, `source_message_id`, `source_badges` set. `badges` are the
  chatter's badges in **your** channel; `source_badges` those in the origin channel.
- `message_id` differs per channel; `source_message_id` is the original. Deleting/replying uses the id
  of the copy in the channel you act in.
- Commands: decide explicitly whether a `!cmd` typed in another streamer's channel should trigger your bot
  (the template ignores them by default).
- Sending: with an **app token**, Send Chat Message / Send Chat Announcement go to the source channel only by
  default (`for_source_only` defaults to `true` since 2025-05-19); pass `for_source_only:false` to fan out.
  With a **user token** they always go to all channels, and setting `for_source_only` is a 400.
- Session events (no authorization required, condition `broadcaster_user_id` only):
  `channel.shared_chat.begin` (`session_id`, `host_broadcaster_user_*`, `participants[]`),
  `channel.shared_chat.update` (same shape; participants changed), `channel.shared_chat.end`
  (`session_id`, host). Current state anytime: `GET /helix/shared_chat/session?broadcaster_id=`.

## 13. Testing

- The Twitch CLI (v1.1.24) **cannot** trigger any `channel.chat.*` event (`twitch event trigger --help` lists
  none), and its mock WebSocket server rejects chat subscription types:
  `POST http://127.0.0.1:<port>/eventsub/subscriptions` → `400 "The combination of values in the type and
  version fields is not valid"` (verified). It still sends `session_welcome` and `session_keepalive`, so you
  can test connection handling: `twitch event websocket start-server -p 8130` → connect to
  `ws://127.0.0.1:8130/ws`.
- CLI control commands (`twitch event trigger … --transport=websocket`, `twitch event websocket reconnect`)
  reach the mock server over a fixed local RPC port — with two mock servers on one machine, they hit the
  first one started. Run one at a time.
- For chat, feed fixtures: `scripts/fixtures/*.json` are the verbatim official examples; wrap them in a
  WebSocket envelope (`metadata.message_type: "notification"`, `subscription_type`) as `scripts/selftest.ts`
  does, or POST them to your webhook handler with a valid HMAC (twitch-eventsub skill).
