# Forest dressing

`createTree(species, seedKey, scale?)` returns connected wood and six distinct canopies as sparse, merged runs on the 0.5 m terrain lattice. `gold`, `pine`, `cherry`, `teal`, `birch`, and `willow` have separate silhouettes and calm, dusk-friendly leaf ramps. Every seed includes the full realm/placement identity. The kit contains no emissive material or indication of a person's presence.

`planForest(seedKey, species, options)` returns stable per-tree positions, scale and seed, with a broken woodland edge, crown spacing, clearing masks, slope/terrain filtering, and a water-distance rule for willow. Pass a `sample` callback from canonical ground/shore data and `canPlace(x,z,radius)` that tests the entire canopy disk against the real protected masks; return `null` for unknown, water, road, build or other protected space and set `reserved` for all occupied or sightline areas. Units are source cells; the callback supplies ground height in cells, slope as rise/run and water distance in cells. Call the planner for a bounded region; callers needing independent streamed regions must supply stable bounds/ownership and remove border duplicates. `createForest` is a compact review fixture that bakes trees and shrubs into one kit; it is limited to 64 trees and a 256-cell radius. Its flat default is a model-review fixture: willow's default ground has an assumed water distance of four cells, not a physical bank. The review does not certify placement against actual water. Production should stream `planForest`'s individual trees instead. Both use separate deterministic feature streams, so undergrowth does not move trees.

Builder adoption: preserve each placement's `seedKey` and species, rasterize `createTree` box runs into the existing grand palette and chunk/halo boundary, then mesh with terrain; don't render individual boxes or treat these visual trees as authoritative colliders. The builder currently maps its own named species and material IDs; it must provide a stable palette translation and culling/cache key before adoption. This folder alone does not change the grand renderer or its physical scene.
